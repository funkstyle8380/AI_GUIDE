# lounge-plan-review — 기획 검수·전달

## 역할과 선택 기준

작성된 기획 산출물에서 빠진 것과 서로 맞지 않는 것을 찾는 단계다. "설계서 검수해줘", "개발에 넘기기 전에 점검해줘", "IA 바뀐 거 설계서에 영향 있는지 봐줘" 같은 요청에 사용한다. 검수 중 발견한 문제를 바로 고치는 것은 요청 범위에 수정이 포함된 경우에만 한다.

## 필요한 입력과 조사 범위

- 필수: 검수 대상 산출물과 버전, 검수 목적(전달 전 점검·변경 영향·현업 검토 전).
- 관련 근거: 요구 목록, IA 최신본, 정책 정의, 결정 기록, 이전 검수 결과.
- 범위: 대상 화면과 같은 정책을 쓰는 다른 화면. 검수하지 않은 범위는 결과에 명시한다.

## 적용과 입력

[루트 지침](../../../AGENTS.md)과 [검수·완료 근거](../../planning.md#review)를 적용한다.

## 작업

1. 요구 목록의 각 항목이 IA 화면이나 정책에 연결되는지 대조한다. 연결되지 않은 요구는 누락 후보로 남긴다.
2. IA의 화면 ID와 설계서의 화면 목록, 화면명이 같은지 확인한다.
3. 같은 정책이 화면마다 다르게 쓰였는지, 정책 정의와 화면 동작이 맞는지 확인한다.
4. 상태·오류·빈 상태·권한 없음·개인정보 표시 기준이 화면마다 정의됐는지 확인한다.
5. 결정 필요 항목에 결정 주체·재개 조건이 있는지, 가안이 확정처럼 표시되지 않았는지 확인한다.
6. 변경 영향 검수라면 바뀐 화면·정책을 참조하는 다른 화면과 이미 전달된 개발 작업을 찾는다.
7. 결과를 결함 / 미정 / 개선 제안으로 나누고, 개발 전달 범위를 확정·가안·결정 필요로 정리한다.

산출물: 검수 결과(항목별 Pass / Fail / Not Run / N/A) / 수정 항목 / 전달 범위 / 남은 결정.

## 결함·미정·개선 제안 구분

- 결함: 요구가 반영되지 않았거나, 산출물끼리 맞지 않거나, 필수 상태가 빠진 것. 근거 위치와 함께 적는다.
- 미정: 결정이 없어 판단할 수 없는 것. 결정 기록과 연결한다.
- 개선 제안: 지금도 동작하지만 더 낫게 할 수 있는 것. 결함과 섞지 않는다.

## 자료 부족·충돌 처리와 다음 단계

비교할 IA·요구 목록의 버전이 다르면 어느 버전 기준으로 검수했는지 명시한다. 검수 뒤 원본이 바뀌면 영향받는 항목을 다시 검수한다. 수정 항목은 해당 단계(lounge-plan-ia·lounge-plan-spec)로 돌려보낸다.

## 결과 형식과 사용 예시

```text
검수 대상·기준: <파일·버전 / 비교한 요구·IA 버전>
결과: <검수 항목 / Pass·Fail·Not Run·N/A / 근거>
결함: <위치 / 내용 / 수정 담당>
미정: <항목 / 결정 주체 / 관련 결정 ID>
개선 제안: <내용>
전달 범위: 확정 <화면 ID> / 가안 <화면 ID> / 결정 필요 <화면 ID>
```

가상 사례: 주문 상세 화면설계서에는 '부분 취소' 버튼이 있지만 취소 정책 정의에는 부분 취소 조건이 없다. 이 경우 정책 일관성을 Fail로 두고, 부분 취소 허용 조건을 결정 필요로 연결하며, 주문 상세의 취소 영역은 '결정 필요' 범위로 전달한다. 실제 검수 결과가 아니다.
