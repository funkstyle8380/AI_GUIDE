# 정책 결정 기록·확인 요청

이 파일은 배포용 양식이며 현재 등록된 실제 결정은 없다. 실제 기록은 [프로젝트의 공유 결정 기록 위치](README.md#shared-records)에 남기고, 개인 가이드 복사본마다 확정 결정을 따로 관리하지 않는다. 기획 중 미정·충돌이 생기면 아래 항목으로 기록하고, 기획 초안과 확정 정책을 구분한다.

```text
ID / 상태: 미정·제안·확정·대체됨
근거: 파일명·버전·시트/슬라이드/화면 링크·확인 날짜
확인한 내용·관찰 범위 / 결정할 질문:
결정 주체: 사업·운영 현업 / 기획 / 개발·연동 (담당 확인 시 이름)
영향 화면·정책 ID / 진행할 범위 / 보류 범위·재개 조건:
결정 내용·결정자·일자·근거·적용 범위:
대체된 결정: 해당할 때
```

예시로, 업셀링을 결제 전 추천으로 볼지 이용권 사용 시점 추천으로 볼지가 미정이면 FO 노출 화면과 BO 설정 화면의 범위가 함께 바뀐다. 결정 전에는 두 방식의 화면 범위와 운영 부담을 비교한 대안을 정리할 수 있지만, 한쪽을 전제로 화면을 확정하지 않는다. 이 예시는 실제 결정 내용이 아니다.

<a id="request-template"></a>
## 현업 확인 요청·개발 질의 답변 — 사람·AI 공통 양식

현업에 확인을 요청하거나 개발 질의에 답할 때 아래 양식을 쓴다. 보내기 전에 관련 IA·설계서·결정·기존 요청에 이미 답이 있는지 확인한다. 한 요청에는 함께 결정할 한 가지 주제만 담는다.

```text
[기획 확인 요청] <메뉴·기능> — <결정할 항목>
대상: <화면 ID·화면명 / 정책 ID>
현재 확인: <자료에서 확인한 내용과 근거 위치>
확인 요청: <실제 상황과 결정할 질문, 선택지가 있으면 선택지>
기획 반영 위치: <결정 후 수정할 IA·화면·정책 항목>
영향: <영향받는 화면·개발 작업, 진행·보류 범위>
결정 주체: <현업 / 기획 / 개발, 모르면 확인 필요>
```

개발 질의에 답할 때는 제목을 `[기획 답변]`으로 바꾸고 '확인 요청' 대신 '답변'과 '설계서 반영 여부'를 쓴다.

'기획 반영 위치'에는 결정된 내용을 어느 화면·정책에 넣을지 쓴다. '검토 부탁드립니다'처럼 범위가 불분명한 요청은 피한다. 선택지는 확정 정책과 구분하고, 기존 결정 ID가 있으면 제목이나 본문에 연결한다.

<a id="request-example"></a>
## 작성 예시 — 실제 검토 결과·정책이 아님

```text
[기획 확인 요청] 프로모션 — 제휴카드 할인과 쿠폰 중복 적용
대상: 주문서 화면 / 프로모션 적용 정책
현재 확인: 보고서와 IA에서 제휴카드 BIN 할인과 쿠폰 적용 화면은 확인했으나, 두 혜택이 동시에 적용 가능한지 기준을 찾지 못했습니다.
확인 요청: 같은 주문에 BIN 할인과 쿠폰을 함께 적용할 수 있나요? 불가하면 사용자가 하나를 고르나요, 유리한 쪽이 자동 적용되나요?
기획 반영 위치: 혜택 적용 정책, 주문서 화면의 혜택 영역 상태
영향: 주문서·결제 화면, 프로모션 등록 화면의 중복 설정 항목. 결정 전에는 주문서 기본 구성만 설계하고 혜택 영역은 보류합니다.
결정 주체: 사업·운영 현업 / 실제 담당 확인 필요
```

<a id="request-usage"></a>
## 직접 작성과 AI 요청

- 사람이 직접 보낼 때: 팀이 쓰는 채널(메일·메신저·이슈 도구)에 양식대로 작성하고, 같은 주제를 논의 중인 스레드가 있으면 그 스레드에 이어서 남긴다.
- AI에게 초안을 요청할 때: 대상 자료와 검토 범위를 주고 이 양식으로 쓰게 한다. 초안만 요청했다면 보내지 않는다.
- AI에게 발송·게시를 요청할 때: 대상·채널·범위를 확인하고, 실제 도구의 발송 기능과 계정 권한을 확인해 수행한다. 발송 결과는 반환된 링크·ID 등 실제 결과로 확인한다. 도구·권한이 없으면 초안을 주고 사람이 보내도록 안내한다. 실패를 발송 완료로 보고하지 않는다.

### AI에게 초안 요청

```text
자료: <IA·설계서·보고서 파일과 범위>
lounge-plan-spec과 공통 확인 요청 양식으로 현업 확인 요청 초안을 써줘.
관련 자료·기존 결정·이전 요청에서 먼저 답을 찾고 중복 질문은 빼줘.
결정 주체별로 나누고, 영향받는 화면과 진행·보류 범위를 포함해줘. 아직 보내지 마.
```

<a id="request-followup"></a>
## 답변 이후 기록

보냈다면 결정 항목에 대상 화면과 요청 링크 또는 ID를 연결한다. 초안이면 '초안·미발송', 사람이 보냈다면 실제 발송 결과를 기록한다.

답변이 오면 결정자·내용·근거·적용 범위를 결정 항목에 반영하고, 보류했던 화면의 진행 범위와 재개 조건을 갱신한다. IA·설계서에 실제로 반영했는지 확인하고 미반영이면 구분해 남긴다. 질문을 보냈다는 사실이나 담당이 확인되지 않은 답변만으로 정책 확정으로 처리하지 않는다.
