# 기획 Workflow

기획자와 AI가 요구·현행 분석부터 IA·화면·정책 설계, 검수와 개발 전달까지 함께 진행하는 공통 기획 프로세스다. 기획자는 범위와 정책 판단을 맡고 AI는 자료 조사·대조·초안·점검·기록을 지원한다. 현업 요구, AS-IS 화면, IA·설계서와 공유 결정을 근거로 작업한다. 스킬 선택은 [루트 지침](../AGENTS.md), 확인 항목은 [기획 기준](planning.md)을 본다.

## 근거가 남는 산출물을 기준으로 협업하기

반복 확인은 프로젝트가 합의한 IA 양식·화면 ID 체계·설계서 템플릿으로 묶고, 기획자와 AI가 같은 파일·버전을 기준으로 작업한다. 양식과 공유 위치는 기획PL이 프로젝트 기준에 맞춰 관리한다. 이 가이드에서 새 양식을 일괄 지정하지 않는다.

작업 시작 시 대상 파일의 버전과 이전 검토 결과를 확인한다. 산출물을 만들 때는 행마다 근거(파일·시트·행, 슬라이드, 화면 링크)를 남기고, 판정이 추정이면 신뢰도와 이유를 함께 적는다. 기획자는 정책 판단과 AI가 확인하지 못한 범위를 확인한다. AI의 완료 보고만으로 검토 완료를 판단하지 않는다. [전체 협업 흐름](../index.html#purpose)을 참고한다.

## 처음 연결할 때

AI가 엑셀·PPT·Figma를 읽고 결과 파일을 만들려면 자료 형식에 맞는 파일 접근 도구가 필요하다. 공용 스킬은 작업 지침이고, MCP는 Figma·문서 도구 같은 외부 자료를 AI 도구에 연결하는 방식이다. 연결과 권한 설정은 각자의 하네스에서 구성한다.

작은 자료 범위로 실제 읽기를 먼저 확인한다. 엑셀은 [시트·행 읽기 기준](planning.md#xlsx-input), PPT는 [슬라이드 읽기 기준](planning.md#ppt-input), Figma는 [연결·범위 기준](planning.md#figma-input)을 적용한다. 반복해서 쓰는 용어·정책·ID 규칙이 쌓이면 [프로젝트 기획 문서](project-docs.md)로 정리한다. 시작 순서는 [HTML 도입부](../index.html#quick-start)를 따른다.

## 작업 흐름

| 단계 | 확인할 내용 | 결과 |
| --- | --- | --- |
| 요구·현행 분석 | 현업 요구, AS-IS 화면·운영 방식, 보고서의 범위·우선순위 | 요구 목록·현행 화면 목록·확인 질문 |
| IA 구성·대조 | 메뉴 구조, 화면 단위, ID 체계, AS-IS↔TO-BE 대응 | IA·대조표·누락/신규 목록 |
| 화면·정책 설계 | 화면 구성·상태·흐름, 업무 규칙, 권한·채널·예외 | 화면설계서·정책 정의·결정 질문 |
| 검수·전달 | 요구 반영·IA 일치·정책 일관성·미정 범위 | 수정 항목·전달 범위·다음 작업 |

단계마다 별도 문서를 만들 필요는 없다. 작은 변경은 필요한 스킬만 쓰고 결과를 짧게 기록한다. 여러 메뉴에 걸친 작업만 공유 위치에 계획·결과를 정리하고 작업 카드와 연결한다. 팀이 이 폴더를 기록 위치로 정했다면 `tasks/PLAN-메뉴.md`를 사용할 수 있다.

## 단계 사이의 연결

- 요구·현행 분석에서 나온 요구 ID와 AS-IS 화면 ID는 IA 대조표의 근거 열로 이어진다. 대조에서 누락으로 판정된 화면은 '반영 / 의도적 제외 / 결정 필요' 중 하나로 처리 방향을 남긴다.
- IA에 확정된 화면 ID만 화면설계서의 대상이 된다. 설계 중 화면이 추가·통합되면 IA를 먼저 갱신하고 설계서에 반영한다. IA와 설계서의 화면 목록이 다르면 어느 쪽이 기준인지 확인한다.
- 정책 정의는 여러 화면에서 공통으로 쓰는 규칙(취소·만료·승인·노출 조건)을 한 곳에 두고 화면설계서에서 참조한다. 같은 규칙을 화면마다 다르게 적지 않는다.
- 검수에서 나온 수정은 해당 단계의 산출물에서 고치고, 변경 이력과 영향받는 화면·개발 작업을 기록한다.

## 프로젝트 기획 문서를 함께 운영하는 권장 확장

처음에는 제공된 자료와 작업·결정 기록으로 시작한다. 같은 용어·정책·ID 규칙을 여러 번 설명하게 되면 프로젝트 문서로 정리하고, 문서 목차에서 이번 작업에 필요한 부분만 선택하게 한다. 설계·검수 후 바뀐 내용은 문서에도 갱신해 다음 기획자·AI 작업으로 이어간다. [운영 예시와 AI 요청 방법](project-docs.md)을 참고한다.

## 미정 정책과 진행 범위

보고서·IA·설계서·회의록 등 제공된 자료와 관련 결정을 먼저 확인한다. 파일·버전·시트 또는 슬라이드, 확인 날짜와 관찰 범위를 남기고 확인한 내용과 미확인·충돌·접근 불가를 구분한다.

| 결정 주체 | 결정할 내용 | 예시 |
| --- | --- | --- |
| 사업·운영 현업 | 판매·취소·환불·노출·승인 등 업무 정책, 서비스 지속 여부 | 업셀링 적용 조건, 프로모션 중복 허용 |
| 기획(PL·담당) | 메뉴 구조, 화면 단위·흐름, 용어, 1차/2차 범위 제안 | 화면 통합 여부, 이력 화면을 상세 탭으로 둘지 |
| 개발·연동 담당 | 데이터 구조·API·외부 연동 방식, 구현 가능 여부·공수 | 공급사 API 연동 방식, 실시간/배치 처리 |

결정 주체가 다른 질문을 한 질의에 섞지 않는다. 정책이 미정이어도 화면 골격·공통 요소·독립 흐름은 먼저 설계할 수 있다. 반면 상태 정의나 승인 흐름 자체가 미정이면 여러 화면의 버튼·노출 조건이 함께 바뀌므로 해당 화면 묶음을 보류하고 재개 조건을 남긴다. 화면 초안은 확정 설계와, AI 제안은 합의된 정책과 구분한다.

## 완료와 인수인계

진행 상태는 Todo / In Progress / Review / Done / Blocked로 남긴다. 기획 산출물의 완료와 현업 승인·개발 반영은 따로 표시한다. 필수 확인이 남아 있거나 결정 필요 항목이 열려 있으면 Done으로 처리하지 않는다.

[작업 기록](task-template.md)에 대상 파일·버전, 변경한 시트·화면 ID, 검수 방법과 결과(Pass / Fail / Not Run / N/A), 남은 결정과 다음 담당을 남긴다. 원본 파일을 수정했다면 변경 이력 시트나 버전 표기를 갱신하고, 별도 파일로 산출했다면 원본 파일명·버전을 결과 파일에 기록한다. 검수 뒤 원본이 바뀌면 영향받는 검수를 다시 하고 이전 결과를 그대로 완료 근거로 쓰지 않는다.

## 공유 기록 위치와 가이드 갱신

개인별 AI 도구는 달라도 같은 프로젝트의 결정·IA·설계서는 함께 확인할 수 있어야 한다. 처음 연결할 때 기획PL과 다음 위치를 정하고 작업 요청에 경로·링크를 남긴다. 이미 정해진 위치가 있으면 재사용한다.

- 공용 가이드 원본·관리 담당과 사용할 버전 또는 커밋. 버전 관리가 없으면 배포일·변경 내역으로 구분한다.
- 결정 기록, IA·설계서 최신본, 현업 확인 요청 목록의 기준 위치. 공유 드라이브·문서 도구·이슈 도구 등 팀이 이미 쓰는 위치를 고르며 새 도구를 만들 필요는 없다.
- 이 폴더의 `decisions.md`와 `task-template.md`는 기록 구조와 양식이다. 개인 복사본마다 실제 결정을 따로 관리하지 않는다.
- 외부 공유가 제한된 자료(고객사 내부 문서, 운영 화면 캡처, 담당자 정보)는 공개 저장소·개인 클라우드에 올리지 않는다. 가이드 저장소에는 양식과 일반 기준만 두고 실제 자료는 링크로 연결한다.
- 복사해서 쓰는 가이드는 원본 위치·기준 버전을 남긴다. 작업을 재개할 때 원본 변경 여부와 관련 결정이 대체됐는지 확인한다.

공유 위치가 아직 없다면 위치를 정할 질문을 남기고 분석·초안 등 독립 작업을 진행한다. 개인 메모는 공유 기록에 반영하기 전까지 팀의 확정 기준으로 취급하지 않는다.

## 개인 하네스

각자 AI 도구에 엑셀·PPT 읽기, Figma 연결, 결과 파일 저장을 연결한다. 공용 원본을 직접 읽는 방식으로 시작할 수 있고, 자동 등록·호출 설정은 개인 환경에서 구성한다. 복사해서 사용하면 폴더 구조와 상대 경로를 유지한다. 산출물 폴더 밖의 가이드는 자동 적용을 전제하지 않으며, 첫 요청과 새 대화·작업 재개 시 가이드의 AGENTS.md와 자료·공유 기록 경로를 전달한다.

<a id="harness-check"></a>
## 사용하면서 검증하고 보완하기

**이 가이드는 작업 지침이다. 연결·스킬 설정만으로 AI의 임의 판단이 막히거나 모든 누락이 발견된다고 보장하지 않는다.** 처음 연결할 때와 AI 도구·연결·지침을 바꾼 뒤에는 작은 실제 작업으로 확인하고, 사용 중 드러난 문제를 보완한다.

- 결과의 각 행이 실제로 읽은 파일·시트·슬라이드로 연결되는지 대조한다. '읽었다'는 보고만으로 지침 준수를 판단하지 않는다.
- 메뉴명만 보고 한 대조를 확정처럼 쓰는지, 자료를 못 읽은 것을 기획 누락으로 단정하는지 확인한다.
- AI가 정책을 확정하거나 없는 화면 ID·근거를 만들면 영향받는 결과를 다시 검토한다. 원인이 자료 연결·지침 누락·기록 단절 중 무엇인지 확인해 해당 범위를 보완한다.
- 보완 뒤 같은 조건으로 다시 확인하고 남은 미확인을 작업 결과에 남긴다. 하네스 확인은 산출물의 현업 검토를 대신하지 않는다.
