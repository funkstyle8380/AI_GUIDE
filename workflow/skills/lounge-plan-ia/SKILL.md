# lounge-plan-ia — IA 구성·대조

## 역할과 선택 기준

메뉴 구조와 화면 목록을 설계·개발이 셀 수 있는 단위로 만드는 단계다. "TO-BE IA 초안 잡아줘", "AS-IS랑 TO-BE IA 대조해줘", "두 버전 IA에서 바뀐 화면 찾아줘" 같은 요청에 사용한다. 화면 내부 구성이나 정책은 다루지 않는다. 화면 목록이 확정돼 있으면 화면·정책 설계부터 시작할 수 있다.

## 필요한 입력과 조사 범위

- 필수: 대상 IA 파일과 시트, 버전, 작업 목적(작성·대조·버전 비교). 대조라면 AS-IS와 TO-BE 양쪽 파일.
- 관련 근거: lounge-plan-discover의 요구 목록·현행 화면 목록, 이전 대조 결과, ID 규칙·용어집, 결정 기록.
- 범위: 대상 영역(APP·FO·BO 등)과 채널, 1차/2차 구분. 요청한 시트가 없으면 임의로 대체하지 않고 어떤 시트를 쓸지 확인하거나 사용한 시트를 명시한다.

## 작업

1. 양쪽 파일의 시트·머리글·행 수를 확인하고, 숨김·필터·병합 셀을 정리해 읽는다. 표지의 총 본수와 실제 행 수가 다르면 기록한다.
2. 화면 단위 기준을 양쪽에 같게 적용한다. 한쪽만 공통 컴포넌트·외부 화면을 포함하면 대조 결과가 왜곡된다.
3. 대조는 ID가 아니라 화면 기능 기준으로 한다. 화면명·상위 메뉴·설명·URL을 함께 보고 판정하며, 판정마다 근거와 신뢰도를 남긴다.
4. 이전 대조 결과가 있으면 승계한 판정과 새로 판단한 판정을 열로 구분한다.
5. 'AS-IS만' 항목은 처리 방향(반영 / 의도적 제외 / 결정 필요)을 붙인다. 판단할 수 없으면 결정 필요로 둔다.
6. TO-BE 안의 품질 이슈(ID 중복, 같은 화면의 다중 모듈 정의, 하위 미정의 메뉴)를 별도 목록으로 남긴다. 원본을 고치지 않는다.
7. 결과 파일은 요약·전체 매핑·판정별 목록·품질 이슈·작성 기준 시트로 구성하고 원본 파일명·버전을 표기한다.

산출물: IA 또는 대조표 / 판정별 건수 / 누락 후보와 처리 방향 / 품질 이슈 / 결정 질문.

## 판정을 내리는 기준

- 이름이 달라도 기능이 같으면 명칭 변경이다. 이름이 같아도 대상(회원/비회원, 앱/웹)이 다르면 별개 화면일 수 있다.
- 여러 AS-IS 화면이 TO-BE 한 화면의 탭·필터·상태로 합쳐졌으면 통합이다. 통합 방식(탭·필터·팝업)을 적는다.
- 화면 설명 없이 메뉴명만 보고 판정했다면 신뢰도를 '낮음'으로 두고 확인 대상에 넣는다.
- 의도적으로 없앤 기능과 빠뜨린 기능은 자료만으로 구분되지 않는 경우가 많다. 결정 기록이나 보고서에 제외 근거가 있을 때만 '의도적 제외'로 판정한다.

## 자료 부족·충돌 처리와 다음 단계

IA 버전마다 화면 수가 크게 다르면 작성 기준이 바뀌었는지 먼저 확인한다. 판정할 수 없는 항목은 결정 필요로 남기고 나머지 대조는 진행한다. 확정된 화면 목록과 결정 필요 항목은 lounge-plan-spec에 전달한다.

## 결과 형식과 사용 예시

```text
대조 범위·근거: <AS-IS 파일·시트·버전 / TO-BE 파일·시트·버전>
작성 기준: <화면 단위·제외 기준·승계 여부>
결과 요약: 일치 n / 명칭변경·통합 n(신뢰도 낮음 n) / AS-IS만 n / TO-BE만 n
누락 후보: <AS-IS ID·화면명 / 처리 방향 / 근거>
품질 이슈: <ID 중복·중복 정의·미정의 메뉴>
결정 질문: <질문 / 결정 주체 / 영향 화면>
```

가상 사례: AS-IS에는 '휴면 계정 해제' 화면이 있고 TO-BE IA의 회원 메뉴에는 대응 화면이 없다. 보고서·결정 기록에 제외 근거도 없다. 이 경우 'AS-IS만 / 결정 필요'로 두고 "휴면 정책을 유지하면 해제 화면이 필요합니다. 유지 여부를 확인해 주세요"를 질문으로 남긴다. 실제 대조 결과가 아니다.
