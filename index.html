기획 AI 협업 가이드

기획자와 AI가 요구·현행 분석부터 IA·화면·정책 설계, 검수와 개발 전달까지 함께하는 공통 기획 프로세스

1. 기획자와 AI가 함께하는 기획 프로세스

이 가이드는 기획자와 AI가 요구·현행 분석, IA 구성, 화면·정책 설계, 검수를 함께 진행하는 공통 기획 프로세스를 설명합니다. 기획자가 범위와 정책 판단을 맡고, AI가 자료 조사·대조, 초안 작성, 누락·충돌 점검을 지원합니다.

현업 요구·AS-IS 화면·IA·공유된 결정을 함께 보고, 근거가 남는 산출물을 기준으로 작업합니다. AI가 만든 대조표·초안을 기획자가 확인하고, 정해지지 않은 정책은 결정 주체에게 묻고, 확인된 결과를 다음 단계로 넘깁니다.

근거가 남는 산출물을 기준으로 협업하기

대조표·설계서의 각 행이 어느 파일·시트·슬라이드에서 나왔는지 남기면, 기획자는 AI 결과를 빠르게 확인하고 다른 담당자는 같은 근거로 이어서 작업할 수 있습니다. 산출물 양식과 화면 ID 체계는 프로젝트에서 합의한 기준을 따릅니다.

  1. 시작할 때: 대상 파일의 버전과 이전 검토 결과를 확인해 어디서부터 이어가는지 정합니다.
  2. 작성할 때: AI가 자료를 읽어 초안·대조표를 만들고, 행마다 근거와 판정 신뢰도를 남깁니다.
  3. 확인할 때: 기획자가 신뢰도 낮은 판정과 결정 필요 항목을 먼저 보고, 정책 판단이 필요한 항목은 결정 주체에게 연결합니다.
  4. 마칠 때: 산출물 위치·버전, 검수 결과, 남은 결정과 다음 담당을 기록합니다. AI의 완료 보고만으로 검토 완료를 판단하지 않습니다.

협업 시작하기

아래 경로와 작업 범위를 채워 AI에 전달합니다. 엑셀·PPT부터 검토한다면 Figma 연결을 먼저 구성할 필요는 없습니다. 공유 기록 위치는 팀이 쓰는 기준 위치를 연결합니다.

가이드: <plan_guide 경로>
기획 자료: <IA 엑셀 파일·시트·버전 / PPT 파일·슬라이드 / Figma 링크>
현행(AS-IS) 자료: <현행 IA·화면 캡처 / 없다면 없음>
공유 기록: <결정·IA 최신본·확인 요청 목록의 기준 위치 / 미정이면 기획PL과 확인>
프로젝트 문서: <용어집·ID 규칙 등 기존 문서 / 없다면 없음>
요청 범위: <현행 분석 / IA 구성·대조 / 화면·정책 설계 / 검수>

지정한 가이드의 AGENTS.md를 직접 읽고, 필요한 SKILL.md를 링크에서 읽어 적용해줘.
등록된 호출 명령은 가정하지 마.
자료의 시트·행·슬라이드 범위를 먼저 확인하고 읽지 못한 부분을 알려줘.
결과의 각 항목에 근거 위치를 남기고, 확인됨·추정·미확인·충돌을 구분해줘.
원본은 수정하지 말고 결과는 별도 파일로 만들어줘.
정책 판단이 필요한 항목은 결정 주체별 질문으로 정리하고,
산출물 위치·남은 확인·다음 작업을 기록해줘.

가이드 복사본의 갱신과 프로젝트 기록 관리는 공유 기록·가이드 갱신 기준을 따릅니다. 가이드는 산출물 폴더 밖에 두어도 되며, 새 대화나 작업 재개 시 위 경로를 다시 전달합니다.

자료 형식별로 전달하는 방법

기획 자료는 엑셀 IA·대조표, PPT 보고서, Figma 화면설계, 회의록·메일로 흩어져 있습니다. 형식마다 AI가 놓치기 쉬운 부분이 다르므로 파일명·버전과 읽을 범위를 함께 지정합니다.

자료함께 전달할 것놓치기 쉬운 부분
엑셀 IA·대조표파일명·버전, 대상 시트, 머리글 행, 비교할 열숨김 시트·행, 필터 상태, 병합 셀의 상위 메뉴명, 표지의 총 본수와 실제 행 수 차이
PPT 보고서·기획서파일명·버전, 슬라이드 번호·제목, 대상 기능이미지 안의 글자, 발표자 노트, 슬라이드마다 다르게 적힌 일정·범위
Figma 화면설계화면·프레임 링크 또는 메뉴 범위, 검토 목적주석·상태 화면·프로토타입 연결, 권한·호출 한도로 일부만 읽힌 경우
회의록·현업 메일일자·참석 주체, 관련 메뉴결정인지 의견인지 구분, 이후 회의에서 바뀐 내용

주의엑셀 파일을 열었다고 모든 시트를 읽은 것은 아닙니다

AI 도구는 첫 시트만 읽거나, 숨김 시트·필터로 가려진 행을 건너뛰거나, 병합 셀을 빈 값으로 읽을 수 있습니다. 시트 목록과 시트별 행 수를 먼저 보고하게 하고, 결과의 건수가 원본과 맞는지 확인합니다.

요청한 시트가 없을 때 비슷한 이름의 시트로 대체했다면 어떤 시트를 썼는지 결과에 남겨야 합니다.

AI 요청 예시

AS-IS: <파일명·버전 / 시트> TO-BE: <파일명·버전 / 시트> 범위: <영역·메뉴 / 채널> lounge-plan-ia로 두 IA를 화면 단위로 대조해줘. 먼저 양쪽 시트의 머리글·행 수·숨김/필터 상태를 알려줘. 판정마다 근거와 신뢰도를 남기고, AS-IS만 남는 화면은 처리 방향을 붙여줘. 원본은 고치지 말고 결과 파일에 원본 파일명·버전을 표기해줘.

AI의 상세 읽기 기준은 엑셀 · PPT · Figma 기준에 있습니다.

AI 도구·MCP·스킬의 역할

기획자는 AI 도구에 작업을 요청합니다. AI 도구는 스킬의 지침을 적용하고, 연결된 도구로 파일을 읽거나 결과 파일을 만듭니다.

구성역할기획 작업에서의 예
스킬작업 순서와 판단 기준IA 대조 시 판정 기준·신뢰도·결과 시트 구성
MCP외부 도구·자료를 AI 도구에 연결Figma 화면 읽기, 문서 도구·드라이브 접근
파일 도구로컬·공유 폴더의 파일 읽기·쓰기엑셀·PPT 읽기, 대조표 파일 생성
하네스AI와 위 도구·권한·설정을 묶은 작업 환경개인별 AI 도구 설정과 연결 상태

스킬 파일이나 Figma 링크를 전달하는 것과 실제 자료에 접근할 도구·권한을 준비하는 것은 별개입니다. 처음에는 작은 화면 하나, 시트 하나로 실제 읽기를 확인합니다.

컨텍스트: AI가 현재 작업에서 참고하는 정보 범위

컨텍스트는 AI가 현재 답변을 만들 때 함께 참고하는 작업 공간입니다. 대화, 지침·스킬, 읽은 엑셀·PPT·화면 내용이 여기에 들어갑니다. IA 수백 행과 보고서 수십 장을 한꺼번에 넣으면 앞에서 확인한 조건을 놓치거나 결과 일부가 빠질 수 있으므로, 한 번 읽은 내용을 끝까지 모두 기억한다고 가정하지 않습니다.

전달 방식장점·적합한 작업단점·보완 방법
화면·시트 하나
대상 화면 링크나 시트·행 범위를 지정		범위가 명확해 빠르게 확인할 수 있습니다. 상세 설계·특정 화면 보완·작은 수정에 적합합니다.진입 조건·전후 화면·공통 정책이 빠질 수 있습니다. 관련 화면을 추가로 지정하거나 AI가 찾아 확인하도록 범위를 줍니다.
메뉴·영역 전체
메뉴 범위와 검토 목적을 함께 전달		메뉴 사이 흐름·정책·누락을 비교하기 좋습니다. IA 대조와 메뉴 단위 설계에 필요합니다.읽는 양이 커서 시간·사용량이 늘고 누락이 생기기 쉽습니다. 구조를 먼저 보고 화면 묶음별로 나눠 확인하며 결과를 기록합니다.

메뉴 전체를 맡길 때

대상: <IA 파일·시트 / Figma 메뉴 링크> 범위: <예: BO 마케팅 메뉴의 프로모션·쿠폰 화면> 먼저 메뉴 구조와 화면 목록을 파악하고, 화면 묶음으로 나눠줘. <우선 검토할 묶음>부터 상세히 읽고, 묶음마다 결과를 기록한 뒤 다음으로 넘어가줘. 각 묶음의 근거 위치·확인한 정책·미정 질문·미확인 범위를 남겨줘.

권장 순서: 구조·화면 목록 확인 → 우선 화면 묶음 상세 확인 → 근거·미정 기록 → 다음 묶음 → 마지막에 묶음 사이 정책·흐름 대조. 구조만 본 상태와 상세 검토 완료를 구분합니다.

2. 문서 구조와 진입점

기획자는 이 HTML에서 전체 작업 방식을 확인하고, AI는 AGENTS.md에서 요청에 맞는 스킬을 고릅니다. 작업·기획 기준은 Markdown 한 곳에서 관리하고 이 안내에서 연결합니다.

plan_guide/
├── index.html                 기획자용 안내
├── AGENTS.md                  시작 지침·스킬 선택
├── assets/                    공통 테마·목차
└── workflow/
    ├── README.md              작업 순서·완료 기준·공유 기록

    ├── project-docs.md        프로젝트 기획 문서 운영
    ├── decisions.md           결정 기록·확인 요청 양식
    ├── task-template.md       작업 기록 양식
    ├── tasks/                 실제 작업 기록(팀이 정한 경우)
    └── skills/                분석·IA·설계·검수

시작 지침 · 기획 기준 · 작업 양식

폴더 전체로 독립해서 사용합니다. 실제 IA·설계서·보고서는 기존 공유 위치에 두고, 이 가이드에는 양식과 일반 기준만 둡니다.

운영 방법과 AI 요청 예시는 프로젝트 기획 문서 운영에 있습니다.

3. 현행 분석과 IA 대조

IA는 설계·개발·테스트 범위를 세는 기준입니다. 한 행이 하나의 화면 상태를 뜻하도록 정리해야 AS-IS와 TO-BE를 같은 단위로 비교할 수 있습니다.

화면 단위로 정리하는 기준

대상처리
일반 화면·레이어 팝업·바텀시트화면으로 등록합니다.
외부 화면(PG 결제창·본인인증·외부 링크)제외하거나 '외부'로 구분합니다.
화면 없는 로직(자동 로그인·리다이렉트·배치)제외하고 관련 화면 비고에 남깁니다.
공통 컴포넌트(GNB·탭바·배너 영역)공통 항목이나 상위 화면 비고로 둡니다.
두 메뉴에서 진입하는 같은 화면하나로 통합하고 진입 경로를 비고에 적습니다.
백업·빈 페이지·404정리 대상 목록으로 따로 둡니다.

제외·통합한 항목은 지우지 않고 별도 시트에 사유와 함께 남깁니다. 앱(MA)·PC웹(PW)·모바일웹(MW)처럼 채널이 나뉘면 화면을 복제하지 않고 채널을 열로 표시합니다.

AS-IS↔TO-BE 대조 판정

판정기준함께 남길 것
일치화면명·기능이 같음양쪽 ID
명칭 변경기능은 같고 이름만 다름판단 근거
통합여러 AS-IS 화면이 TO-BE 한 화면으로 합쳐짐통합 방식(탭·필터·팝업)
AS-IS만TO-BE에서 대응 화면을 찾지 못함처리 방향: 반영 / 의도적 제외 / 결정 필요
TO-BE만AS-IS에 없는 신규 화면신규 요구 근거

확인'AS-IS만'은 곧바로 누락이 아닙니다

의도적으로 없앤 기능일 수 있습니다. 보고서나 결정 기록에 제외 근거가 있을 때만 '의도적 제외'로 두고, 근거가 없으면 결정 필요로 남깁니다.

화면 설명 없이 메뉴명만 보고 판정했다면 신뢰도를 '낮음'으로 표시합니다. 기획자는 신뢰도 낮은 판정부터 확인합니다.

대조 중 발견한 TO-BE IA의 품질 이슈(ID 중복, 같은 화면의 다중 모듈 정의, 하위가 정의되지 않은 메뉴)는 원본을 고치지 않고 별도 목록으로 남겨 IA 담당에게 전달합니다. 상세 절차는 IA 구성·대조 스킬에 있습니다.

4. 화면설계와 정책 정의

화면설계서는 개발·디자인·QA가 같은 화면을 같은 의미로 읽게 만드는 문서입니다. 여러 화면에서 쓰는 업무 규칙은 정책 정의로 분리하고, 화면설계서에서는 정책 ID로 참조합니다.

항목확인할 내용
화면 정보화면 ID·명칭·채널·진입 경로·이전/다음 화면
구성 요소영역별 요소, 표시 데이터와 출처, 정렬·검색·페이징
상태초기·로딩·데이터 없음·오류·권한 없음·점검
동작버튼별 결과, 확인 팝업, 성공·실패 메시지
입력 검증필수 여부·형식·길이·중복 확인·오류 문구
정책 참조적용 정책 ID와 화면 내 반영 위치
미정결정 필요 항목·결정 주체·임시 가정

정책 문장은 "~할 수 있다 / 없다"처럼 판정 가능하게 씁니다. "적절히", "필요시" 같은 표현은 결정 질문으로 바꿉니다. 상태가 있는 대상(이용권·주문·프로모션·승인 요청)은 상태 목록과 전이 조건을 표로 정리하고, 상태마다 화면에 보이는 버튼·문구를 연결합니다.

현업 확인 요청 — 사람·AI 공통 양식

자료만으로 정할 수 없는 정책은 아래 양식으로 결정 주체에게 묻습니다. 보내기 전에 관련 IA·설계서·결정·이전 요청에 이미 답이 있는지 확인하고, 한 요청에는 함께 결정할 한 가지 주제만 담습니다.

[기획 확인 요청] <메뉴·기능> — <결정할 항목> 대상: <화면 ID·화면명 / 정책 ID> 현재 확인: <자료에서 확인한 내용과 근거 위치> 확인 요청: <실제 상황과 결정할 질문, 선택지가 있으면 선택지> 기획 반영 위치: <결정 후 수정할 IA·화면·정책 항목> 영향: <영향받는 화면·개발 작업, 진행·보류 범위> 결정 주체: <현업 / 기획 / 개발, 모르면 확인 필요>

작성 예시 · 실제 검토 결과나 확정 정책이 아닙니다

[기획 확인 요청] 프로모션 — 제휴카드 할인과 쿠폰 중복 적용 대상: 주문서 화면 / 혜택 적용 정책 현재 확인: 보고서와 IA에서 제휴카드 BIN 할인과 쿠폰 적용 화면은 확인했으나, 두 혜택을 함께 적용할 수 있는지 기준을 찾지 못했습니다. 확인 요청: 같은 주문에 BIN 할인과 쿠폰을 함께 적용할 수 있나요? 불가하면 사용자가 고르나요, 유리한 쪽이 자동 적용되나요? 기획 반영 위치: 혜택 적용 정책, 주문서 화면의 혜택 영역 상태 영향: 주문서·결제 화면, 프로모션 등록 화면의 중복 설정 항목. 결정 전에는 주문서 기본 구성만 설계하고 혜택 영역은 보류합니다. 결정 주체: 사업·운영 현업 / 실제 담당 확인 필요

'기획 반영 위치'에는 결정된 내용을 어느 화면·정책에 넣을지 씁니다. "검토 부탁드립니다"처럼 범위가 불분명한 요청은 피합니다.

사람이 직접 보내거나 AI에게 요청하는 방법

  • 직접 보낼 때: 팀이 쓰는 채널에 양식대로 작성하고, 같은 주제를 논의 중인 스레드가 있으면 이어서 남깁니다.
  • AI에게 초안을 요청할 때: 대상 자료와 범위를 주고 이 양식으로 쓰게 합니다. 초안만 요청했다면 보내지 않습니다.
  • AI에게 발송을 요청할 때: 대상·채널과 도구 권한을 확인해 보내고, 반환된 링크·ID로 결과를 확인합니다. 도구·권한이 없으면 초안을 받아 사람이 보냅니다.

답변 이후 기록 방법은 결정 기록 기준을 따릅니다. 개발 질의에 답할 때도 같은 양식을 [기획 답변]으로 바꿔 사용합니다.

5. 미정 정책과 작업 범위

업무 정책은 현업이, 화면 구성·흐름·용어는 기획이, 데이터 구조·연동 방식은 개발이 결정합니다. 결정 주체가 다른 질문은 한 요청에 섞지 않습니다.

결정 주체결정할 내용예시
사업·운영 현업판매·취소·환불·노출·승인 정책, 서비스 지속 여부업셀링 적용 조건, 프로모션 중복 허용
기획(PL·담당)메뉴 구조, 화면 단위·흐름, 용어, 1차/2차 범위 제안화면 통합 여부, 이력을 상세 탭으로 둘지
개발·연동 담당데이터 구조·API·외부 연동 방식, 구현 가능 여부공급사 연동 방식, 실시간/배치 처리

확인상태·승인 흐름이 미정이면 여러 화면이 함께 바뀝니다

독립된 조회 화면은 먼저 설계할 수 있습니다. 반면 상태 정의나 승인 흐름 자체가 미정이면 목록·상세·등록 화면의 버튼과 노출 조건이 모두 영향을 받습니다. 이런 경우 해당 화면 묶음을 보류하고 재개 조건을 남깁니다.

결정 전 임시 가정으로 설계한 부분은 '가안'으로 표시해 확정 설계와 구분합니다.

6. Workflow와 스킬 선택

스킬은 요청 유형별 절차와 산출물을 정리한 작업 지침입니다. 요구·현행 분석, IA 구성·대조, 화면·정책 설계, 검수·전달의 네 역할만 둡니다.

스킬에 무엇을 맡기고 어떤 결과를 받는가

스킬이런 요청에받는 결과
요구·현행 분석
lounge-plan-discover		"현행 화면 정리해줘", "보고서에서 이 메뉴 요구만 뽑아줘"요구 목록, 현행 화면·제외 목록, 충돌·확인 질문
IA 구성·대조
lounge-plan-ia		"AS-IS랑 TO-BE IA 대조해줘", "두 버전에서 바뀐 화면 찾아줘"대조표, 판정별 건수·신뢰도, 누락 후보 처리 방향, 품질 이슈

하나의 메뉴가 네 단계를 지나는 예시

가상의 'BO 쿠폰 일괄 발급' 사례입니다. 실제 요구·정책·검토 결과가 아닙니다.

  1. 요구·현행 분석: 회의록에서 "쿠폰 일괄 발급을 엑셀로 수기 처리한다"는 운영 의견을 찾습니다. 현행 IA에는 화면이 없으므로 요구 후보로 올리고, 1차 포함 여부를 현업 확인 질문으로 남깁니다.
  2. IA 구성·대조: 현업이 1차 포함을 확인하면 TO-BE IA에 등록·결과 조회 화면을 추가하고 ID를 부여합니다. 기존 쿠폰 원장 화면과 중복 정의되지 않았는지 확인합니다.
  3. 화면·정책 설계: 업로드 양식·검증 오류·부분 실패 처리를 설계합니다. 발급 후 취소 가능 여부가 미정이면 결과 화면의 취소 버튼만 보류하고 나머지는 진행합니다.
  4. 검수·전달: 요구 목록·IA·설계서가 서로 맞는지 확인하고, 취소 영역은 '결정 필요'로 표시해 개발에 전달합니다.

7. 검수·전달·변경 관리

검수는 산출물 사이가 서로 맞는지 확인하는 단계입니다. 아래 항목을 이번 범위에 맞게 선택하고, 결과를 Pass / Fail / Not Run / N/A로 남깁니다.

검수 항목확인 방법
요구 반영요구 목록의 각 항목이 IA 화면이나 정책에 연결되는가
IA 일치IA 화면 ID·화면명과 설계서 화면 목록이 같은가
정책 일관성같은 정책이 화면마다 다르게 쓰이지 않았는가
상태·예외오류·빈 상태·권한 없음·개인정보 표시가 정의됐는가
미정 정리결정 필요 항목에 결정 주체·재개 조건이 있는가

진행 상태는 Todo / In Progress / Review / Done / Blocked로 남깁니다. 개발에 넘기는 범위는 확정 / 가안 / 결정 필요로 나누고, 확정된 IA·설계서를 바꾸면 변경 이력(일자·화면 ID·내용·사유·요청자)을 남겨 영향받는 개발·QA 작업에 알립니다.

확인결정 필요 항목이 열려 있으면 완료로 표시하지 않습니다

Done은 작업 카드에 적은 범위의 완료입니다. 기획 검수 통과·현업 승인·개발 반영을 구분합니다.

작업 기록에 산출물 위치·버전, 검수 결과, 남은 결정과 다음 담당을 남깁니다.

8. 개인 하네스 연결

각자 사용하는 AI 도구에 엑셀·PPT 읽기, Figma 연결, 결과 파일 저장을 연결합니다. 공용 가이드는 파일을 직접 읽는 방식으로 시작하면 됩니다. 자동 등록은 개인 환경에서 구성하고, 복사해서 쓸 때는 폴더 구조와 상대 경로를 유지합니다. 작은 실제 작업 하나로 자료 읽기부터 결과 기록까지 이어지는지 확인합니다.

고객사 내부 문서·운영 화면 캡처·담당자 정보처럼 외부 공유가 제한된 자료는 공개 저장소나 개인 클라우드에 올리지 않습니다. 가이드 저장소에는 양식과 일반 기준만 두고, 실제 자료는 공유 위치의 링크로 연결합니다.

사용 시 주의지침과 스킬은 실제 작업에서 확인하며 보완해야 합니다

지침과 연결 설정만으로 AI의 임의 판단이 막히거나 모든 누락이 발견된다고 보장하지 않습니다. 처음 연결할 때와 AI 도구·연결·지침을 바꾼 뒤에는 작은 실제 작업으로 확인하고, 드러난 문제를 수정합니다.

  • 결과의 각 항목이 실제로 읽은 파일·시트·슬라이드로 연결되는지 확인합니다.
  • 메뉴명만 보고 한 판정을 확정처럼 쓰는지, 자료를 못 읽은 것을 기획 누락으로 단정하는지 봅니다.
  • 정책을 임의로 확정하거나 없는 화면 ID·근거를 만들면 영향받는 결과를 다시 검토하고, 자료 연결·개인 설정·공통 스킬 중 원인을 보완합니다.
  • 이 확인은 산출물에 대한 현업 검토를 대신하지 않습니다.

상세 기준은 사용 중 검증·보완을 참고합니다.

처음 요청할 때는 도입부의 시작 프롬프트를 사용합니다. 기록 위치와 갱신 방법은 공유 기록·가이드 갱신 기준을 따릅니다.
