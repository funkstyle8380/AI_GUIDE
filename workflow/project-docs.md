# 권장 확장 — 기획 산출물을 프로젝트 지식으로 쌓고 운영하기

이 가이드로 실제 작업을 시작한 뒤, 메뉴와 참여자가 늘어나면 프로젝트 기획 문서를 함께 운영하는 방식을 권장한다. 작업마다 같은 용어·ID 규칙·공통 정책을 다시 설명하지 않고, 기획자와 AI가 필요한 근거를 찾아 이어서 작업할 수 있게 하는 것이 목적이다.

<a id="roles"></a>
## 공용 가이드·프로젝트 문서·작업 기록의 역할

| 구분 | 담을 내용 | 관리 방식 |
| --- | --- | --- |
| 공용 plan_guide | 분석·IA·설계·검수의 공통 방법과 양식 | 공용 원본에서 관리하고 여러 프로젝트가 참조 |
| 프로젝트 기획 문서 | 그 프로젝트의 용어·ID 규칙·공통 정책·IA 최신본 위치 | 기획PL이 실제 산출물·결정 근거와 연결해 관리 |
| 결정·작업 기록 | 무엇을 왜 결정했는지, 이번에 무엇을 바꾸고 검수했는지 | 팀의 공유 위치에서 이력·상태·담당을 관리 |

프로젝트 문서는 반복해서 쓰는 현재 기준이고, 결정·작업 기록은 그 기준이 만들어지거나 바뀐 근거다. 같은 정책의 확정본을 여러 곳에서 따로 고치지 않는다. IA·설계서 원본은 기존 공유 위치를 유지하고, 문서에서는 설명과 링크만 연결한다.

<a id="start-small"></a>
## 언제부터 무엇을 정리하면 좋은가

| 반복되는 상황 | 먼저 정리할 문서 | 다음 작업에서 얻는 점 |
| --- | --- | --- |
| 화면 ID·모듈 코드를 매번 설명함 | ID 규칙·모듈 목록·채널 표기 | IA·설계서·대조표의 ID가 맞춰짐 |
| 같은 용어를 사람마다 다르게 씀 | 용어집(이용권·사용처·판매채널 등) | 화면 문구와 정책 문장이 일관됨 |
| 승인·취소·노출 규칙을 여러 메뉴에서 씀 | 공통 정책 정의와 관련 결정 | 메뉴별로 다른 규칙이 생기는 일을 줄임 |
| IA 최신본이 어느 파일인지 헷갈림 | 산출물 목록(파일·버전·위치·담당) | 잘못된 버전으로 작업하는 일을 줄임 |
| 담당자가 바뀌거나 메뉴를 인계함 | 메뉴별 현황(완료·보류·결정 대기) | 남은 확인과 재개 조건을 바로 파악 |

작은 수정마다 별도 문서를 만들 필요는 없다. 반복해서 쓰는 내용을 작업 기록에서 골라 정리한다. 프로젝트 문서를 운영한다고 새 스킬을 만들어야 하는 것은 아니다. 기존 네 스킬에 문서 위치를 연결하는 것으로 시작할 수 있다.

<a id="structure"></a>
## 추천 구조 예시

아래는 예시이며 현재 프로젝트에 존재한다는 뜻은 아니다.

```text
project-planning/
├── README.md               문서 목차·산출물 위치·담당·기준 버전
├── glossary.md             용어집
├── id-rules.md             화면 ID·모듈 코드·채널 표기
├── policies/               공통 정책(승인·취소·노출·혜택 적용)
├── menus/                  메뉴별 현황·보류·결정 대기
└── decisions/              결정 기록(또는 공유 도구 링크)
```

<a id="flow"></a>
## AI 작업과 문서 갱신을 연결하는 흐름

1. 작업을 시작할 때 문서 목차에서 이번 메뉴와 관련된 정책·용어·ID 규칙만 골라 읽는다.
2. 작업 중 기존 문서와 다른 내용을 발견하면 바로 고치지 않고 충돌로 기록한다.
3. 결정이 나면 결정 기록을 먼저 갱신하고, 현재 기준 문서에 반영한다.
4. 작업을 마칠 때 바뀐 기준 문서와 미반영 항목을 작업 기록에 남긴다.

<a id="ai-request"></a>
## AI에게 문서 확장을 요청하는 방법

```text
기획 가이드: <plan_guide의 AGENTS.md 경로>
대상 자료: <최근 작업 기록·결정 기록·IA 파일>
반복해서 설명한 용어·ID 규칙·정책을 찾아 프로젝트 문서 후보로 정리해줘.
문서마다 담을 내용과 근거 위치를 제시하고, 충돌하는 내용은 따로 표시해줘.
실제 파일은 내가 확인한 뒤 만들어줘.
```
